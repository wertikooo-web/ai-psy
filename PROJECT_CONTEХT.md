# PROJECT_CONTEXT.md

## Проект

Название: **TRANSCRIPT AI · PSY**

Тип: Next.js веб-приложение для психологов.

Цель: создать рабочее пространство, где психолог может хранить клиентов, консультации, транскрипты, материалы, историю клиента и получать AI-анализ консультаций.

---

## Текущий стек

* Next.js 15
* TypeScript
* Tailwind
* локальные JSON / mockData
* OpenAI API
* OpenAI Whisper API планируется
* Railway для deploy
* GitHub для репозитория

Supabase пока не подключён.

---

## Карточка клиента

У клиента должны быть вкладки:

1. Обзор
2. Консультации
3. История клиента
4. Материалы

### Обзор

Краткая информация о клиенте.

### Консультации

Список консультаций клиента.

Консультация не должна отображаться как просто имя файла `1.m4a`.

Лучше показывать:

* Консультация #1;
* дата;
* статус аудио;
* статус транскрипта;
* статус анализа.

### История клиента

Структурированный контекст клиента.

Разделы:

* Основные темы;
* Рабочие гипотезы;
* Ресурсы клиента;
* Значимые события;
* Что уже исследовали;
* Что требует уточнения;
* Важные заметки психолога.

### Материалы

Импорт старых материалов:

* общая история клиента;
* заметки психолога;
* старые анализы GPT;
* транскрипт прошлой встречи;
* другое.

## Новая консультация

Нужно поддерживать 3 источника:

### 1. Аудиозапись

Форматы:

* mp3;
* m4a;
* wav.

Путь:

аудио → Whisper → transcript → analysis.

### 2. Готовый транскрипт

Форматы:

* txt;
* md;
* вставка текста вручную.

Путь:

transcript → analysis.

### 3. Текстовые заметки

Ручной текст психолога.

Путь:

notes → analysis.

В UI обязательно показывать, если это заметки, а не полный транскрипт.

## Страница консультации

Главная рабочая страница продукта.

Структура:

### Верхняя шапка

Показывает:

* имя клиента;
* сессию / дату;
* статус;
* длительность;
* действия;
* кнопку назад.

### Три панели

Левая:

🎙 Транскрипт
Реплики клиента и психолога.

Средняя:

🧠 AI-анализ
Ключевые наблюдения, гипотезы и направления.

Правая:

💬 Чат по консультации
Вопросы по этой конкретной сессии.

---

## Важный UX по странице консультации

Каждая панель должна прокручиваться независимо.

Транскрипт может быть очень длинным.

AI-анализ может быть очень длинным.

Чат может быть очень длинным.

Поэтому нельзя использовать один общий scroll всей страницы.

Нужна структура:

* fixed sidebar;
* fixed consultation header;
* 3 panel layout;
* panel header fixed;
* panel content scrollable;
* chat input fixed bottom.

Страница `/debug-analysis` нужна для проверки:

* какие файлы базы знаний подключаются;
* какой prompt собирается;
* какой размер prompt;

## Railway

Railway используется для deploy.

Важно:

`data/` и `public/uploads/` на Railway не являются надёжным постоянным хранилищем.

После redeploy данные могут потеряться.

Это нормально для MVP, но не подходит для реального коммерческого использования.

Supabase понадобится позже.

## Supabase

Supabase пока не подключать.

* импорт материалов;

* загрузка консультации;

## Ближайший правильный путь

1. Починить layout и scroll страницы консультации.
2. Замкнуть сценарий TXT/MD transcript → OpenAI analysis → результат на странице.
3. Подключить Whisper для аудио.
4. Сделать clientContext из Истории клиента и Материалов.
5. Потом думать о Supabase.

---

## Главный принцип

Не строить инфраструктуру раньше продукта.

Сначала доказать, что психолог может реально работать:

клиент → консультация → транскрипт → анализ → чат → история клиента.
