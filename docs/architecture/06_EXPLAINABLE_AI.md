# 06 — Explainable AI

> Статус: **частично реализовано** (EvidenceTooltip, AnalysisBlocks).

## Принцип

Психолог должен понимать, ПОЧЕМУ AI сделал тот или иной вывод — не только ЧТО он сказал.

Это особенно важно в психологическом контексте: слепое доверие AI-выводам без понимания их основания — профессиональная ошибка.

## Реализованное

### AnalysisBlocks

Второй LLM-проход после генерации анализа. Извлекает из текста анализа структурированные блоки:
- Координаты в тексте (для подсветки)
- `isInterpretive: boolean` — является ли утверждение интерпретацией (а не наблюдением)
- `evidenceTooltip: string[]` — объяснение вывода в 2–4 предложениях
- `confidence: 'high' | 'medium' | 'low'`
- `evidenceRefs` — ссылки на речевые паттерны из `analysisEvidence`

### EvidenceTooltip

Иконка 🔍 рядом с интерпретивными утверждениями в тексте анализа.
При наведении — попап с объяснением "Как AI пришёл к этому выводу".

**Что убрано намеренно:**
- Badge уверенности ("Средняя уверенность") — создавал ложное ощущение точности
- Атрибуция ("Основано на данных сессии") — очевидно и без этого

### AnalysisEvidence (речевые паттерны)

Извлекается при первом анализе, кэшируется по `sourceHash`.
Содержит: ключевые темы, частые слова, эмоциональные маркеры, паттерны речи.
Передаётся во второй проход (extractBlocks) для генерации `evidenceTooltip`.

## Что не реализовано

- **Ссылки на конкретные реплики**: tooltip мог бы показывать цитату из транскрипта, на основании которой сделан вывод. Требует изменения схемы blocks + UI.
- **История объяснений**: как менялась уверенность AI по одной теме от сессии к сессии.
- **"Почему не упомянул X"**: возможность спросить AI почему он не включил что-то в анализ.

## Принципы, которые нельзя нарушать

1. Tooltip никогда не показывает сырой JSON и не упоминает слово "JSON".
2. `evidenceTooltip` — это объяснение для психолога, не техническая метаинформация.
3. Блоки без `isInterpretive = true` не получают иконку 🔍 (фактические наблюдения не требуют объяснения).
