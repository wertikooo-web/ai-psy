# 02 — AI Architecture

## Провайдер

OpenAI GPT-4o. Конфигурируется через `lib/llm.ts` и `lib/data/userProfile.ts` (поле `aiModel`).
Провайдер абстрагирован через интерфейс `LLMProvider` — при необходимости можно добавить Anthropic/Gemini без изменения бизнес-логики.

## TPM-ограничения

Лимит: **30 000 TPM** (tokens per minute) на бесплатном / низком тарифе OpenAI.

Принятые решения:
- `TPM_SAFE_LIMIT = 27 000` — буфер 3k на дисперсию токенизации
- `PROMPT_CHARS_PER_TOKEN = 4` — калибровано на реальном overflow: 31 429 токенов / ~114k символов
- Динамический guard в `generateAnalysis()`: измеряем собранный prompt, обрезаем transcript если `estimatedTotal > TPM_SAFE_LIMIT`

## Режимы анализа

Шесть режимов (`AnalysisMode`), каждый с отдельным набором файлов базы знаний:

| Режим | `maxTokens` | Фокус |
|-------|-------------|-------|
| `working` | 3 000 | Ключевые темы и динамика |
| `deep` | 6 000 | Паттерны, противоречия, подробный разбор |
| `hypothesis` | 3 000 | Рабочие гипотезы |
| `therapist_process` | 4 000 | Интервенции и позиция психолога |
| `gestalt` | 4 000 | Гештальт-подход |
| `next_session` | 2 500 | Темы и вопросы для следующей встречи |

## База знаний (KB)

Файлы `.md` из `knowledge-base/` директории. Режим получает свой набор файлов через `getKnowledgeFilesForMode()`.

Правила форматирования вынесены в единую константу `UNIVERSAL_FORMAT_RULES` в `lib/knowledgeBase.ts`. Каждый режим описывает только **содержание**, не форматирование.

## Двухпроходная архитектура

**Проход 1 — анализ** (`generateAnalysis`):
- Собирает системный prompt: KB + правила форматирования + запрос клиента + transcript
- Вызывает LLM, получает текст анализа

**Проход 2 — извлечение блоков** (`extractBlocks`):
- Берёт текст анализа + evidence (речевые паттерны)
- Короткий LLM-вызов (4 000 токенов), Zod-валидация
- Возвращает структурированные `AnalysisBlock[]` с координатами в тексте

Оба прохода выполняются последовательно внутри одного HTTP-запроса к `/api/analyze`.

## Сжатие транскриптов (Map-Reduce)

Если transcript > 8 000 токенов (~12 000 символов):
1. Разбивается на чанки по 12 000 символов
2. Каждый чанк сжимается отдельным LLM-вызовом до 350–450 слов
3. Результат кэшируется в `consultations.compressed_transcript` (jsonb)
4. Кэш валидируется по `sourceHash` — инвалидируется при изменении transcript

Sleep 12 000ms после всех чанков — чтобы TPM восстановился перед основным анализом.

## Клиентский контекст

`assembleClientContext()` в `/api/analyze/route.ts` собирает параллельно (Promise.allSettled):
1. Карточка клиента (запрос, темы, фокус)
2. История клиента (client_history по секциям)
3. Материалы клиента (до 10, кроме therapist_notes, до 2 000 символов каждый)
4. Предыдущие консультации с анализами (последние 2, до 400 символов каждый)
