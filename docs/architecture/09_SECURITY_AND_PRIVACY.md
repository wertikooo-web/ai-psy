# 09 — Security & Privacy

## Природа данных

Транскрипты психологических сессий — **чувствительные персональные данные** (в ряде юрисдикций: специальная категория персональных данных). Это накладывает особые обязательства.

## Что реализовано

### Передача данных в OpenAI

Транскрипты и материалы клиента передаются в OpenAI API для анализа. Это осознанное архитектурное решение. Психолог должен быть уведомлён об этом при первом использовании.

**Что НЕ передаётся в AI:**
- `therapist_notes` из client_materials (явно исключены в `assembleClientContext`)
- Идентификаторы клиента, его контакты, персональные данные (только имя и запрос)

### Supabase RLS

Включён на всех таблицах. В текущей однопользовательской версии правила минимальны, но инфраструктура готова к расширению.

### Server-only DAL

Все запросы к БД — через `lib/data/*.ts` файлы с пометкой `SERVER ONLY`. Клиент не имеет прямого доступа к Supabase.

### Audio

Аудиофайлы хранятся в Supabase Storage. После транскрипции психолог может удалить аудио (`audioDeletedAt`). Транскрипт остаётся.

## Что нужно реализовать

### Уведомление о передаче данных в AI
При первом анализе показывать явное предупреждение: "Текст сессии будет передан в OpenAI для анализа".

### Право на удаление (GDPR/CCPA)
Soft delete реализован (`deleted_at`). Но нет механизма полного удаления данных клиента включая связанные записи и файлы Storage.

### Шифрование на уровне приложения
Supabase шифрует данные at-rest, но не end-to-end. При SaaS: рассмотреть шифрование особо чувствительных полей (content материалов, текст транскрипта) перед сохранением в БД.

### Аудит-лог
Кто и когда запускал анализ, создавал/удалял данные. Сейчас нет. Нужен при SaaS.

### Retention policy
Через сколько времени данные автоматически удаляются? Для психологических данных — актуальный вопрос.

## Принципы, которые нельзя нарушать

1. `therapist_notes` никогда не попадают в AI-prompt.
2. Персональные данные клиента не включаются в URL-параметры.
3. API-ключи только в env-переменных, никогда в коде или логах.
4. При логировании ошибок не пишем содержимое транскриптов.
