# Product Backlog

## Отложенные функции

### Резюме

Статус: Отложено  
Приоритет: Не текущий  
Условие возврата: после завершения поиска, Telegram, аналитики и стабилизации связей данных.

Функцию «Резюме» пока не реализовывать. Не добавлять кнопку, modal, dropdown, API route, background job, prompt, cron, embeddings, отдельную оплату, новую таблицу или скрытый experimental-компонент без отдельного явного задания.

#### Возможные будущие сценарии

Резюме консультации:
- строится по одной конкретной консультации;
- будущие источники: транскрипт, заметки консультации, анализы, evidence, договоренности, следующий шаг;
- результат: основные темы, важные моменты, интервенции психолога, реакции клиента, договоренности, план следующей встречи и список источников.

Резюме по клиенту:
- строится по нескольким консультациям клиента;
- будущие источники: консультации, анализы, заметки, запросы, история клиента, наблюдения;
- результат: актуальные темы, повторяющиеся паттерны, изменения за период, важные договоренности, незавершенные вопросы, следующие шаги и ссылки на реальные источники.

Подготовка к следующей встрече:
- отдельный практический режим, потенциально полезнее общего резюме;
- будущие источники: последняя консультация, последние анализы, активные запросы, важные заметки, предыдущие договоренности, незавершенные действия;
- результат: что важно помнить, что проверить, к чему вернуться, какие договоренности были, какие темы остались открытыми.

#### Возможное размещение

В консультации:
- будущая кнопка «Резюме консультации» внутри конкретной консультации.

В карточке клиента:
- будущая кнопка «Подготовка к следующей встрече» или «Резюме по клиенту».

Не размещать в оплатах, настройках, календаре, общем блокноте, общей аналитике всех клиентов или рядом с каждой короткой заметкой.

#### Принципы будущей реализации

- Использовать только реальные данные проекта.
- Не придумывать факты и не дополнять отсутствующую информацию.
- Не смешивать данные разных клиентов.
- Каждый вывод должен быть связан с реальным источником: консультацией, анализом, заметкой, запросом или историей клиента.
- Не ставить диагнозы и не выдавать гипотезы как факты.
- Период должен быть явно выбран и показан в результате.
- Если резюме сохраняется, хранить дату создания, источники, период, версию данных, модель и статус «может быть устаревшим».

#### Архитектурная заметка

Правильный будущий поток:

```text
пользователь выбирает период и источники
-> сервер получает реальные записи
-> сервер формирует ограниченный набор фрагментов
-> LLM создает краткое резюме
-> результат показывается вместе с источниками
```

Неправильный поток:

```text
LLM получает доступ ко всей базе
-> сама ищет
-> сама решает
-> сама формирует вывод без проверки
```

LLM должна получать только подготовленные сервером данные.

#### Причина отсрочки

Резюме имеет смысл только после стабилизации базовых данных и связей:
- стабильный поиск;
- корректные связи клиентов и консультаций;
- работа Telegram;
- загрузка аудио;
- транскрибация;
- анализы;
- актуальная аналитика;
- безопасность данных;
- единый источник истины.
